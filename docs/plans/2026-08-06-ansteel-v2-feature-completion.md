# Ansteel 协议 v2 功能补全方案

> 状态：待实施（P0 两项已定位根因，可直接开工）
> 日期：2026-08-06
> 定位：把 r84-r98 暴露的失败重新定义为"协议应有的功能未补全"，按功能集分阶段补齐。

## 一、背景与结论

三角色协议在 FrontierMath（4/5）与 Omni-MATH（首批 3/5 正确）上证明核心治理有效。
剩余失败可归类为三类，全部是**本该有的功能缺失**，而非架构错误：

| 失败类别 | 表现 | 缺的功能 |
| --- | --- | --- |
| 计算能力 | Q4/Q5 只读算不出整数 | agent 计算工具（bash）— 已补 |
| 收敛控制 | 2 轮固定上限，或"发现更多 bug"被误判为发散 | 自适应轮次 + 收敛信号 — 已补，启发式待修正 |
| 输出纪律 | 无界生成撞上限、格式修复误杀 | 超长强制 + 格式容错 — 已补超长强制，容错待修 |
| 共识正确性 | Q1 三方一致算错（367879 vs 367707） | 强制独立验证方法 — 未补（P1） |

## 二、功能清单与优先级

### P0：立即实施（有明确根因，改动+测试）

**F1. 自适应启发式修正**
- 问题：b8321f48 第 2 轮 QA 用 bash 独立发现 2 个真 bug（QA-3/QA-4），新问题 1→2 触发"发散即停"，但这是**发现更多 bug = 有进展**，不是分歧发散。
- 方案：`shouldExtendRevisionRounds` 放宽——只要 (a) 上一轮问题全部被 RESOLUTION 关闭（有进展）且 (b) 本轮新问题数 ≤ 上一轮 × 2（容忍小幅增长），允许续轮；保留"重复提已解决问题 / 增长过猛（>2×）/ 无进展"即停。
- 验证：新增单元测试（1→2 续轮、1→3 停止、无进展停止、2× 边界）；用 b8321f48 重跑验证。
- 风险：低。只放宽"有实质进展时"的续轮，门禁不放松。

**F2. 格式修复容错**
- 问题：935e5d89 的 QA 修订在格式修复中改动了措辞，`formatRepairPreservesNonMarkerContent` 逐字节校验失败 → 误杀。
- 方案：格式修复（marker/sections）的 preserve 校验从"非标记内容逐字一致"改为"**结构完整性**"：修复后必须保留原响应中的所有 `VERDICT` / `ISSUE` / `RESOLUTION` / `NO ISSUES` 标记（规范化后），且必填段落齐全；允许措辞精简与重排。over-length 修复天然改内容，不适用 preserve 校验（当前已如此）。
- 验证：新增测试（修复后保留标记但改措辞 → 通过；修复后丢标记 → 拒绝）；用 935e5d89 重跑验证。
- 风险：中低。需要确认"丢标记"检测覆盖足够，防止标记作弊。

### P1：本轮补全

**F3. bash 计算可靠性**
- 问题：r95 90 次 bash 执行 45 次失败，多为解释器/路径问题（python 不在 PATH、Windows 环境差异）。
- 方案：
  - 协议配置增加 `bashInterpreter`（默认解析到 `python312` 实际路径，可显式指定）；
  - 工具定义在提示词中给出可用的计算示例（如 `python -c "..."`、`python - <<'EOF'`）；
  - 失败重试：bash 执行瞬时失败（<1s 且非 timeout）允许自动重试 1 次。
- 验证：用 10 道 Omni-MATH 题统计 bash 成功率提升。
- 风险：中。计算命令越界（访问工作区外文件）需保持路径校验。

**F4. 强制独立验证方法（共识正确性）**
- 问题：Q1 三方一致接受 1/e 猜想（错误值 367879），无独立验证兜底。
- 方案：共识形成前，强制 QA（或任一非 TL 角色）提供**独立验证方法**：
  - work card 必须记录"验证方法"：与 TL 不同的算法/工具/数值途径（如 TL 用筛法，QA 用解析公式或另一实现）；
  - 若无法独立验证（只读限制或时间），必须显式标注 `L4 未独立验证` 并在共识里禁止给出确定整数答案（改为拒绝共识或明确近似）。
  - 协调器校验：共识阶段要求 `<verification-method>` 块存在，否则拒绝。
- 验证：用 Q1 重跑，验证"无独立验证 → 拒绝或标注"路径；用 Q4/Q5（有独立验证）回归。
- 风险：中高。会增加角色输出要求，可能触发超长/格式问题——需与 F2 联动。
