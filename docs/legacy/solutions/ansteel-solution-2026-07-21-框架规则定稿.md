## 2. 修正后的完整规则集（含全部条件）

### R1 置信度标注与提升规则（含 C1）
- L1🟢已验证 / L2🟡高可信 / L3🟠待验证 / L4🔴存疑（定义同前）。
- **【C1】L4→L2 提升必须附 URL；推理型断言可附推理链替代 URL。**
  - 因为：L4 是"存疑/未知"，直接跳到 L2"高可信"是大幅置信度跃迁，必须有可核验依据。
  - URL 适用于事实型断言（寄存器地址、API 行为）；推理链适用于推理型断言（架构权衡、设计取舍）。
  - 禁止：无 URL 也无推理链就把 L4 标为 L2。

### R2 摘要与上下文传递规则（含 C4）
- 每轮结束生成《第 X 轮摘要》，默认 1000 字以内。
- **【C4，优先】摘要必须完整保留全部 L3/L4 断言原文，此要求优先于 1000 字限制。**
  - 因为：L3/L4 是最需要后续验证/推翻的断言，摘要若裁剪会丢失关键风险信号。
  - 实操：若 L3/L4 原文使摘要超 1000 字，摘要可超限；L1/L2 部分仍应精简。
- 摘要须含：TL 子问题、SE 可行方案、QA 关键质疑、**全部 L3/L4 断言原文**。

### R3 冲突引用规则（含 C3）
- **【C3】引用冲突片段必须包含完整限定条件，不得断章取义。**
  - 因为：脱上下文引用会造成"假冲突"（如"ADC 采样时间 10µs"在不同源阻抗下含义不同）。
  - 实操：引用须含前提条件（芯片型号、时钟、外设、温度范围等限定词）。

### R4 4-A 机制规则（含 C2、C7）
- **【C2】4-A 产出的断言，其与既有内容的"冲突/补充"性质由 QA 裁决，SE 不得自判。**
  - 因为：SE 是方案提出者，有"自证补充而非冲突"的利益倾向，需 QA 中立裁决。
- **【C7】P0-0 阶段 4-A 推翻机制暂不生效。**
  - 因为：P0-0 是单模型内部验证，无外部审查员（Codex），4-A 缺乏跨模型制衡基础。
  - P0-0 阶段发现冲突时，按常规 QA 否决→SE 修正流程处理，不触发 4-A 推翻。

### R5 超时与进度保存规则（含 C5）
- **【C5】单次 CLI 调用（单次 task）超时 = 300 秒；整体讨论超时 = 45 分钟（软限制）。**
- 超时处理：**必须保存当前进度到文件**，不得静默丢弃。
  - 因为：steps/超时截断是回测报告 T1 风险点，强制保存避免"讨论进行一半丢失"。
- 软限制含义：45 分钟是目标值，非硬截断；超时后优先完成"保存进度+输出当前结论"再退出。

### R6 文件查找规则（含 C6）
- **【C6】glob 多版本命中时取最新版本（按修改时间）；必须有 fallback（取不到最新时退回第一个/报错明确）。**
- **【C6 降级】"路径缓存"降为 P2 可选，P0-0 不强制实现。**
  - 因为：路径缓存是性能优化，非正确性需求；P0-0 优先保证流程跑通。

### R7 流程完整性规则（P0-0 验收 A1-A5）
- **A1**：9 次 task 调用（3 轮×3 角色）全部成功。
- **A2**：7 个环节不缺（立项/方案/质疑/修正/验证/合议/归档）。
- **A3**：3 份轮次摘要 + 1 份最终方案 md。
- **A4**：每轮含 L1-L4 标注；L3/L4 在摘要中按 R2 保留原文。
- **A5**：单次 task < 300 秒，整体 < 45 分钟。

## 4. 诚实边界声明（单模型上限 L2）

### 4.1 单模型置信度上限
- 单一模型（即使 3 角色）下的所有"已验证"结论，**置信度上限 = L2**。
- 因为：同一模型的 3 角色共享同一知识库和推理偏差，无法交叉验证知识盲区（QA Q1，L2）。

### 4.2 L1 授予标准（单模型阶段收紧）
- 单模型阶段，**L1 仅授予**：有工具调用实际输出支撑的断言（URL 内容、命令执行结果、文件读取内容）。
- 模型"自述验证过"不算 L1，最多 L2。
- 因为：回测报告 T5 显示"未实际运行测试"，模型可能"声称验证而未验证"。

### 4.3 框架不保证消除幻觉
- 框架价值：结构化流程 + 强制标注不确定性 + **降低（非消除）幻觉**。
- 框架不保证：100% 无幻觉。最终决策权在用户。

### 4.4 定稿生效条件
- **形式生效**：规则集 R1-R8 即日作为框架执行规范。
- **实测生效**：待 P0-0 按 A1-A5 全绿后激活。
- 在 P0-0 未绿前，**不得对外宣称"框架可用/已验证"**。
