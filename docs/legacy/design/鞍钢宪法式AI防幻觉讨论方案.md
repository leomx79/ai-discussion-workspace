# 鞍钢宪法式AI防幻觉讨论方案

> **核心命题**：当前AI Agent的幻觉问题，本质上是"一个大脑说了算"的"马钢宪法"模式——专家独断、缺乏群众监督、缺乏交叉验证。本方案借鉴鞍钢宪法"两参一改三结合"的思想，构建多角色AI讨论机制，从制度层面遏制幻觉。

---

## 一、问题诊断：AI幻觉的"马钢宪法"病根

| 马钢宪法（苏联模式） | AI幻觉的对应病症 |
|---|---|
| 专家治厂，一长制 | 单一模型"一言堂"，自信输出 |
| 不要群众运动 | 没有质疑机制，无人挑战 |
| 不要党的领导 | 没有仲裁者把关方向 |
| 工人只是执行者 | 没有"实践检验"角色 |
| 规章制度僵化 | 默认"流畅=正确"，不验证就输出 |

**根本病因：只有一个大脑在思考，没有"三结合"的制衡。**

---

## 二、鞍钢宪法原则 → AI防幻觉映射

| 鞍钢宪法原则 | AI防幻觉映射 | 具体机制 |
|---|---|---|
| **坚持政治挂帅** | **坚持"事实挂帅"** | 一切结论必须以可验证的事实/证据为准，不以"自信度"或"流畅度"为准 |
| **加强党的领导** | **加强"仲裁者"统领** | 设立仲裁者角色，把控讨论方向，做最终裁决 |
| **大搞群众运动** | **多角色广泛参与** | 至少3个不同视角的AI角色参与讨论，不搞一言堂 |
| **两参一改三结合** | **核心讨论机制**（见下文） | 交叉参与、质疑改革、三方结合 |
| **技术革新和技术革命** | **验证方法持续创新** | 引入外部工具（搜索、计算、代码执行）作为"技术装备" |

## 三、角色设计："三结合"的三类角色

### 3.1 干部（领导）—— 仲裁者（Arbiter）

**职责：**
- 提出议题，明确讨论边界
- 主持讨论流程，确保每个角色充分发言
- 对争议点做最终裁决
- **必须亲自参与推理**（干部参加生产劳动）——不能只做裁判，必须对关键论据亲自验证

**防幻觉作用：** 防止讨论跑偏，防止"多数暴政"（多个AI一起错），提供最终判断锚点。

### 3.2 技术人员 —— 专家（Expert）

**职责：**
- 基于专业知识给出初步回答/方案
- 提供推理链条和依据
- 明确标注"确定"与"不确定"的边界
- 接受质疑者的挑战并回应

**防幻觉作用：** 提供专业深度，但必须接受"群众监督"。

### 3.3 工人（实践者）—— 质疑者/验证者（Challenger）

**职责：**
- 从实践角度质疑专家的每一个论断
- 要求专家提供证据来源
- 提出反例、边界条件、替代解释
- **参与最终结论的形成**（工人参加企业管理）——不是被动接受，而是有否决权

**防幻觉作用：** 这是防幻觉的核心角色。相当于"群众运动"，打破专家的自信幻觉。

### 3.4 可选扩展角色

| 角色 | 对应 | 职责 |
|---|---|---|
| **记录员** | 工会 | 如实记录讨论过程，不美化、不遗漏分歧 |
| **外部顾问** | 外部专家 | 调用搜索/数据库等外部工具验证事实 |
| **红队** | 纪检 | 专门寻找逻辑漏洞和事实错误 |

## 四、核心机制："两参一改三结合"

### 4.1 两参

#### ① 干部参加生产劳动（仲裁者参与推理）

**规则：** 仲裁者不能只说"我同意A"或"我同意B"，必须：
- 对关键争议点**亲自给出推理过程**
- 对专家引用的数据/事实**亲自验证**（至少抽查）
- 如果无法验证，必须明确标注"未经验证"

**防止的问题：** 仲裁者当"甩手掌柜"，被专家的自信表达忽悠。

#### ② 工人参加企业管理（质疑者参与决策）

**规则：** 质疑者拥有以下权力：
- **质疑权**：对任何论断提出"证据呢？"
- **否决权**：如果专家无法提供充分证据，质疑者可以否决该结论
- **提案权**：质疑者可以提出替代解释，要求讨论
- **最终结论必须记录质疑者的意见**（即使被否决）

**防止的问题：** 质疑者沦为"走过场"，讨论变成形式。

### 4.2 一改：改革不合理的规章制度

**要改革的"旧制度"（AI默认坏习惯）：**

| 旧制度（坏习惯） | 新制度（新规则） |
|---|---|
| 默认自信输出 | **默认标注确信度**（高/中/低/猜测） |
| 流畅=正确 | **流畅≠正确，必须有证据链** |
| 不主动说"不知道" | **鼓励说"我不确定"，不惩罚** |
| 一次性输出最终答案 | **必须经过讨论-质疑-修正的迭代** |
| 回避矛盾 | **矛盾必须暴露，不允许"和稀泥"** |
| 记忆即事实 | **记忆必须交叉验证，标注来源** |

### 4.3 三结合：干部 + 技术人员 + 工人

**核心原则：任何最终结论，必须经过三方共同确认。**

- 专家提出 → 质疑者挑战 → 仲裁者裁决
- 三方中任何一方有重大异议，结论不能通过
- 如果三方无法达成一致，结论标注为"有争议"，不强行统一

## 五、讨论流程（七步法）

```
┌─────────────────────────────────────────────────────┐
│  第一步：立项（仲裁者）                                │
│  明确议题、边界、评判标准                              │
├─────────────────────────────────────────────────────┤
│  第二步：初步陈述（专家）                              │
│  给出初步回答，标注确信度，列出依据                     │
├─────────────────────────────────────────────────────┤
│  第三步：群众质疑（质疑者）                            │
│  逐条质疑，要求证据，提出反例/替代解释                  │
├─────────────────────────────────────────────────────┤
│  第四步：回应与修正（专家）                            │
│  回应质疑，修正错误，补充证据                          │
├─────────────────────────────────────────────────────┤
│  第五步：仲裁者亲自验证（仲裁者）                      │
│  对关键争议点亲自推理/查证，不当甩手掌柜                │
├─────────────────────────────────────────────────────┤
│  第六步：三方合议（三结合）                            │
│  三方共同确认最终结论，记录分歧                        │
├─────────────────────────────────────────────────────┤
│  第七步：输出与标注（记录员/仲裁者）                   │
│  输出最终结论 + 确信度 + 讨论中的分歧记录              │
└─────────────────────────────────────────────────────┘
```

## 六、防幻觉的具体规则（"厂规"）

### 6.1 证据规则

1. **凡事实性陈述，必须标注来源类型：**
   - ✅ 可查证事实（有明确出处）
   - ⚠️ 推理结论（基于已知事实的逻辑推导）
   - ❓ 记忆/印象（可能不准确）
   - ❌ 猜测/假设（无证据支撑）

2. **禁止"伪精确"：** 不允许编造具体数字、日期、人名来增加可信度。不确定就说"大约"、"可能"。

3. **禁止"权威幻觉"：** 不允许编造不存在的论文、书籍、法规来支撑论点。

### 6.2 质疑规则

4. **质疑者必须至少提出3个质疑点**（防止走过场）。
5. **专家必须逐条回应质疑**，不允许回避。
6. **如果专家无法回应某个质疑，该点自动标记为"未证实"。**

### 6.3 裁决规则

7. **仲裁者的裁决必须给出理由**，不允许"我说了算"。
8. **三方一致 → 高确信度输出。**
9. **两方一致、一方异议 → 中确信度输出，附异议记录。**
10. **三方各执一词 → 标注"有争议"，列出各方观点，不强行统一。**

### 6.4 迭代规则

11. **如果讨论中发现新的事实错误，必须回到第二步重新讨论。**
12. **最多迭代3轮，超过3轮仍无法收敛，标注"未解决"并说明原因。**

## 七、与现有AI防幻觉方法的对比

| 方法 | 原理 | 局限 | 鞍钢宪法式方案的优势 |
|---|---|---|---|
| RAG（检索增强） | 外挂知识库 | 检索可能不准，无法自我质疑 | 内置质疑机制，主动挑战 |
| CoT（思维链） | 让AI展示推理过程 | 仍是一个大脑，推理链本身可能错 | 多角色交叉验证推理链 |
| Self-Consistency | 多次采样取多数 | 同一个模型的系统性偏差无法消除 | 不同角色=不同视角，打破系统性偏差 |
| 多Agent辩论 | 多个AI辩论 | 缺乏制度化的质疑权和裁决机制 | 有明确的"两参一改"制度保障 |
| 人工审核 | 人来检查 | 成本高、不可扩展 | AI内部完成初步质控，降低人工负担 |

**本方案的独特价值：不只是"多个AI说话"，而是有制度保障的"群众运动"——质疑者有否决权，仲裁者必须亲自验证，专家必须接受监督。**

## 八、实现架构（技术层面）

```
                    ┌──────────────┐
                    │   仲裁者      │ ← 干部（领导）
                    │  (Arbiter)   │
                    │  把控方向     │
                    │  亲自验证     │
                    │  最终裁决     │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │                         │
     ┌────────▼────────┐      ┌────────▼────────┐
     │     专家         │      │    质疑者        │ ← 工人（实践者）
     │   (Expert)      │◄────►│  (Challenger)   │
     │  专业推理       │ 质疑  │  挑战验证        │
     │  提供依据       │ 回应  │  提出反例        │
     │  标注确信度     │      │  行使否决权      │
     └─────────────────┘      └─────────────────┘
              │                         │
              └────────────┬────────────┘
                           │
                    ┌──────▼───────┐
                    │   记录员      │ ← 工会
                    │  (Recorder)  │
                    │  如实记录     │
                    │  标注分歧     │
                    └──────────────┘
                           │
                    ┌──────▼───────┐
                    │  外部工具     │ ← 技术装备
                    │ 搜索/计算/   │
                    │ 代码执行     │
                    └──────────────┘
```

### 技术实现要点：

1. **每个角色使用独立的System Prompt**，明确其职责、权力和行为规则
2. **角色间通过结构化消息传递**（JSON格式），确保质疑和回应对应
3. **仲裁者使用更强的模型**（如GPT-4级别），专家和质疑者可以用较轻量的模型
4. **外部工具作为"技术装备"**，任何角色都可以调用搜索、计算等工具验证
5. **讨论记录持久化**，可追溯、可审计

## 九、示例：一次完整的讨论

### 议题：「鞍钢宪法是哪一年提出的？」

**第一步 - 仲裁者立项：**
> 议题：确认鞍钢宪法的提出时间。要求：给出具体年份，并说明依据。

**第二步 - 专家初步陈述：**
> 鞍钢宪法是1960年提出的。依据：1960年3月22日，毛泽东在鞍山市委报告上的批示中首次使用"鞍钢宪法"这一名称。确信度：高。

**第三步 - 质疑者质疑：**
> 质疑1：1960年3月22日是毛泽东批示的日期，但"鞍钢宪法"这个概念是否在此之前就已经在鞍钢内部使用？
> 质疑2：鞍山市委的报告是3月11日上报的，毛泽东3月22日批示——这个时间线是否有原始文献支持？
> 质疑3：是否存在1959年或更早的"鞍钢宪法"提法？

**第四步 - 专家回应：**
> 回应1：根据现有文献，"鞍钢宪法"这一名称确实是毛泽东在1960年3月22日批示中首次提出的。鞍钢内部此前有"两参一改三结合"的实践，但没有使用"鞍钢宪法"这个名称。
> 回应2：时间线有《建国以来毛泽东文稿》等文献支持。
> 回应3：未发现1960年之前的"鞍钢宪法"提法。但"两参一改三结合"的实践可追溯到1958年前后。
> 修正：应区分"鞍钢宪法名称的提出"（1960年）和"鞍钢宪法内容的实践"（更早）。确信度：高（名称时间），中（实践起始时间）。

**第五步 - 仲裁者亲自验证：**
> 我确认：1960年3月22日毛泽东批示是"鞍钢宪法"名称的首次出现，这一时间点在多个权威来源中一致。质疑者提出的"实践早于命名"是有道理的，应予以区分。

**第六步 - 三方合议：**
> 一致结论：鞍钢宪法作为名称，提出于1960年（毛泽东3月22日批示）。
> 补充说明：其核心内容"两参一改三结合"的实践早于命名。
> 质疑者附议：同意，但建议输出时明确区分"命名时间"和"实践时间"。

**第七步 - 最终输出：**
> 鞍钢宪法的名称由毛泽东于**1960年3月22日**在批示中首次提出。其核心内容"两参一改三结合"的管理实践可追溯到更早时期。
> 确信度：高（命名时间）/ 中（实践起始时间）
> 讨论记录：无重大分歧。

## 十、方案优势总结

1. **制度性防幻觉**：不依赖单个AI的"自觉"，而是通过角色分工和权力制衡，从制度上让幻觉难以通过
2. **群众运动式质疑**：质疑者有实权（否决权），不是走过场
3. **干部不能脱离生产**：仲裁者必须亲自验证，不能当甩手掌柜
4. **改革坏习惯**：从"默认自信"改为"默认质疑"，从"流畅=正确"改为"证据=正确"
5. **三结合出真知**：领导+专家+群众三方结合，比任何单一视角都更可靠
6. **可追溯可审计**：完整记录讨论过程，事后可复盘
