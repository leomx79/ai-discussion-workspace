# Ansteel 自适应预算与恢复设计

## 目标

将 Ansteel 的自适应时间、工具预算和跨 epoch 恢复改为可强制、可持久化、可由 CLI 回归验证的协调器行为。固定预算配置不变。

## 约束

- 三角色治理、不可变项目截止时间和 fail-closed 语义保持不变。
- 自适应项目工具上限是硬上限，实际可消费上限为固定项目上限和自适应项目上限中的较小值。
- 非验证和非会签阶段不得侵占 `protectedVerificationToolCalls`。最多两轮修订时必须至少预留十次最小门禁调用；每个验证和最终会签阶段只在仍为所有后续必经门禁保留最低额度后才可消费。
- 每个 epoch 从自己的开始时刻计时。恢复保持项目硬截止时间，但开始新的 epoch 时重置 epoch 时钟。
- checkpoint 只能保存合法状态转换，必须包含下一合法动作、完整协调器状态和当前有效角色身份。
- 恢复必须拒绝任何影响角色身份、提示、权限或回退链的配置变化。

## 架构

`ansteel-discussion.ts` 在构造共享工具预算时计算有效项目上限，并在每个阶段开始时设置后续必经门禁仍需保留的工具数。预算对象在执行工具前先持久化候选项目使用量；写入失败时拒绝执行，不允许产生无法恢复的调用。

`ansteel-run.ts` 把 `epochStartedAt`、实际角色身份和下一合法动作写入 checkpoint。更新函数通过状态转换表拒绝把终态重新标为可恢复，或跳过协调器允许的状态。项目恢复使用持久化的项目 deadline，并以恢复时刻作为新 epoch 起点。

## 验收

1. 当固定上限大于自适应上限时，实际工具预算不能超过自适应上限。
2. 普通阶段达到预留边界时被拒绝；验证和最终会签阶段仍能消费预留。
3. epoch 暂停后恢复，下一阶段获得新的 epoch 时限，项目硬截止时间不变。
4. checkpoint 的下一动作、回退身份和治理台账随提交更新；非法状态倒退被拒绝。
5. GitHub 治理和交付工作流执行自适应测试。
6. 离线构建的模型数据检查通过；在线模型拉取失败仅作为外部网络失败报告。
